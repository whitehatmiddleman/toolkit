Do I have a usable GPU?

First confirm the machine has a discrete GPU, then that ffmpeg can see its encoder. Listing the hardware:

Windows — open dxdiag, or run in PowerShell:

Get-CimInstance Win32_VideoController | Select-Object Name

Linux:

lspci | grep -Ei 'vga|3d|display'

Macs accelerate through VideoToolbox, which this generator's GPU options (NVENC / AMF) don't target — use CPU there.

NVIDIA (NVENC)

Needs an NVIDIA GPU plus a current driver. Check the driver and that the card is visible:

nvidia-smi

A table with your GPU and a driver version means the driver is fine. Then confirm ffmpeg has the encoder:

ffmpeg -encoders | grep nvenc

You should see h264_nvenc and hevc_nvenc. Final end-to-end test:

ffmpeg -f lavfi -i testsrc=size=1280x720:rate=30:duration=3 -c:v h264_nvenc out.mp4

Success means you're ready. Cannot load libcuda or Cannot init CUDA means the driver is missing or too old.

AMD (AMF)

AMF is effectively Windows-only and needs the AMD Adrenalin driver. Confirm the encoder exists:

ffmpeg -encoders | findstr amf

Look for h264_amf and hevc_amf, then test:

ffmpeg -f lavfi -i testsrc=size=1280x720:rate=30:duration=3 -c:v h264_amf out.mp4

On Linux, AMD cards usually accelerate through VAAPI instead (check vainfo). VAAPI uses a different command shape this generator doesn't produce — on Linux AMD, CPU is the reliable choice here.

Shells & batch mode

The Shell selector by the command box only changes output where shells actually differ: the batch-folder loop and the silent-clip duration probe. Plain single commands are identical across bash, PowerShell, and cmd.

For cmd, the batch loop is shown in interactive form (single %). Inside a .bat file, double them: %f becomes %%f.

List the acceleration backends your build supports with ffmpeg -hwaccels. If hardware encoding fails, switch the encoder to CPU — always works, just slower.
